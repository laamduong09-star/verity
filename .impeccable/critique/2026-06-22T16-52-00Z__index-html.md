### Anti-Patterns Verdict

**Start here: does this look AI-generated?** No. No gradient text, no side-stripe borders (the top hairline is full-width and documented as intentional), no eyebrow/numbered scaffolding, no identical hero-metric template. The three stat cards differ meaningfully by icon and color rather than being a copy-pasted grid. It reads as a deliberately designed surface that's actually following its own DESIGN.md.

**Deterministic scan** (`detect.mjs` on `index.html`):
- `overused-font`: Space Grotesk flagged as a common AI default (true, but paired with Inter for a real typographic reason per DESIGN.md's "Numbers-Are-Display Rule").
- `single-font`: false positive. The page loads and uses both Space Grotesk and Inter; the detector likely only pattern-matched part of the `<link>` tag.
- `em-dash-overuse`: 5 em-dashes found, spread across 5 distinct bilingual strings (title, 2x disclaimer, 2x modal copy), not clustered in one paragraph. Low severity, real but minor.

No browser-overlay pass was run (no dev server active this session); findings come from source inspection and the CLI detector only.

### Overall Impression

This is a well-considered, on-brand calculator — the "Graph Paper Calm" identity from DESIGN.md actually shows up in the code, not just the doc. The biggest gap isn't taste, it's that two things the project's own documentation promises aren't implemented: reduced-motion support and form-label association. Both are concrete, fixable, and currently false advertising in DESIGN.md.

### What's Working

- **Two-Accent Rule in practice**: teal consistently means "positive outcome," blue consistently means "interactive/decorative" — genuinely disciplined, not just stated.
- **Numbers-Are-Display Rule**: every calculated value uses `tabular-nums` + Space Grotesk, even in the dense breakdown table.
- **Bilingual structure**: `.en`/`.vi` siblings with `display: none` on the inactive language are correctly hidden from assistive tech, and every string has a same-weight counterpart.

### Priority Issues

**[P1] Form labels aren't programmatically associated with their inputs**
- Why it matters: Every `<label class="field-label">` wraps only the bilingual text spans — the actual `<input>` is a sibling with no `for`/`id` link. A screen reader user hears "500, spin button" with zero context.
- Fix: Add `for="initial"` (etc.) to each `<label>`; IDs already exist on the inputs.
- Suggested command: `/impeccable audit`

**[P1] `prefers-reduced-motion` is fully unimplemented, despite being a named rule in this project's own DESIGN.md**
- Why it matters: DESIGN.md explicitly states the custom cursor, drifting hero dots, `fadeUp`, and `countPop` should respect reduced motion with a fallback. None of that exists in `style.css`.
- Fix: Wrap the cursor's rAF loop and the keyframe animations in reduced-motion checks.
- Suggested command: `/impeccable harden`

**[P1] Nav has no responsive handling, and has already crossed the threshold DESIGN.md flagged as needing one**
- Why it matters: DESIGN.md's own Navigation section says it "needs a collapse/scroll pattern before the nav grows past 5 items." The nav already has 5 items plus logo and language toggle, with zero media queries.
- Fix: Add a collapse pattern below ~700px.
- Suggested command: `/impeccable adapt`

**[P2] Dead nav links give no feedback**
- Why it matters: Recommend, Jargon, Credit, and Family Split point to `href="#"` with no "coming soon" treatment.
- Fix: Disable visibly (`aria-disabled` + reduced opacity) or add a "Coming soon" badge.
- Suggested command: `/impeccable clarify`

**[P2] No input validation or clamping**
- Why it matters: `min`/`max`/`step` are HTML attributes only; the JS does nothing with them, so out-of-range values silently produce a nonsensical chart/table.
- Fix: Clamp values in `update()` and surface an inline message for out-of-range input.
- Suggested command: `/impeccable harden`

### Persona Red Flags

**Sam (Accessibility-Dependent User)**: Tabbing into any input announces only the value and control type, not what the field is for. The canvas chart also has no accessible name or fallback text (secondary gap — the numbers are duplicated in stat cards/table).

**Casey (Distracted Mobile User)**: The topbar (logo + 5-item nav capsule + lang toggle) has zero responsive treatment and is likely to overflow on phone widths.

**Mai (Bilingual First-Time Saver — project-specific)**: "Annual interest rate" has no inline definition or example of a realistic value, despite PRODUCT.md's "Plain language first" principle. Dollar amounts also stay in `en-US` formatting when switched to VI — likely fine for a US-based bilingual audience, but worth a deliberate confirmation.

### Minor Observations

- `z-index` uses two unscaled magic numbers (cursor: 200, modal: 100) rather than a semantic scale.
- `<label class="field-label">` is reused on stat cards with no associated form control — semantically invalid, visually harmless.
- The `single-font` detector finding is a false positive — worth adding to `.impeccable/critique/ignore.md` if it resurfaces.
